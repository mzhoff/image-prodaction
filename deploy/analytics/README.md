# Профиль Метрики для публичной беты

Подготовлен для отдельного, явно согласованного выпуска. Создание этих файлов
не включает отправку событий в текущем локальном или серверном окружении.

`beta.public.env` содержит только три публичные настройки: `live`, счётчик
`112833712` и домен `production.apption.space`. Его нельзя подставлять в локальный
Compose. Локальный `debug` и production default `off` остаются прежними.

`image-production-beta.json` — реестр счётчика **REVERIE Production**, домена,
Compose project и 37 браузерных целей; `serverGoals` содержит ещё 9 целей Identity/Telegram. `goalId` нужен для администрирования и
отчётов Метрики; браузер вызывает `reachGoal` по имени события `ip_*`, а не по
этому числу. В реестре также сохранён подтверждённый снимок настроек приватности
счётчика. Скрипт проверяет конфигурацию выпуска; настройки самого счётчика он не
читает и не меняет.

## Проверка без секретов и без запуска сервисов

Из корня репозитория, на поддерживаемом проектом Node.js 24:

```bash
node --test scripts/analytics-release-profile.test.mjs
node scripts/check-analytics-release.mjs \
  --env-file .env.production.example \
  --env-file deploy/analytics/beta.public.env \
  -f compose.production.yaml \
  -f compose.timeweb.yaml \
  -f compose.egress.yaml
```

Последняя команда выполняет только `docker compose config`. Она проверяет
итоговый `web.environment`, сохраняет полный результат только в памяти и выводит
лишь публичные counter ID, домен и число целей. Контейнеры, образы, сети и данные
не изменяются.

## Подключение к следующему согласованному выпуску Timeweb

В конфигурацию конкретного release включить эти публичные файлы рядом с остальными
Compose-файлами. Для интерполяции использовать существующие защищённые runtime и
release env, затем **последним env-file** — `deploy/analytics/beta.public.env`.
Обычные production, Timeweb и egress overlays сохраняются. Если выпуск использует
дополнительный `compose.nextrelease.yaml`, передать его **последним Compose-файлом**
и в валидатор, и в последующие команды выпуска.

Порядок аргументов для проверки перед запуском (пути к существующим защищённым
файлам задаёт процедура выпуска):

```bash
node scripts/check-analytics-release.mjs \
  --env-file "$runtime_env" \
  --env-file "$release_env" \
  --env-file deploy/analytics/beta.public.env \
  -f compose.production.yaml \
  -f compose.timeweb.yaml \
  -f compose.egress.yaml \
  -f compose.nextrelease.yaml
```

Если дополнительного release overlay нет, последний `-f` исключается. Проверку
нужно выполнить с тем же окружением shell и тем же набором файлов, которые затем
использует одобренный выпуск. После проверки менять их нельзя без повторной
проверки. Скрипт сам ничего не разворачивает и не активирует.

Compose отдаёт переменным shell приоритет над `--env-file`; более поздний
Compose overlay также может заменить `web.environment`. Поэтому правильного
содержимого одного env-файла недостаточно: валидатор отклонит другой счётчик,
дополнительный домен, другой `APP_BASE_URL`, mode `off/debug` или старый
`reverie-stage` project. Значения секретов при отказе не выводятся.

Профиль не подключён автоматически к старому `deploy/server/reverie-ci-deploy`,
который обслуживает отдельный legacy staging, и не меняет CI workflow.
При смене публичного домена необходимо отдельно согласовать привязку счётчика,
обновить этот реестр и публичный профиль, затем повторить проверку.

Сквозная воронка, серверный секрет и порядок миграции: [контракт онбординга](../../docs/analytics-onboarding-contract.md). Новые цели проверены 22 сентября 2026; публичная доставка ещё не подтверждена.

Дашборд активации содержит пять виджетов, включая три сквозные воронки на семь
дней. Их ID и шаги — `activationFunnels` в реестре. `activation-segments.json`
содержит 28 API-сегментов и отдельно 23 категории, сохранённые в интерфейсе.
Внутренний UserID и категории выдаёт защищённый `/api/account/analytics-profile`;
имена и свободный текст исключены. Вебвизор ограничен маскированной анкетой.
Проверка настоящих событий и записей на публичном домене выполняется после
публикации; созданные настройки не доказывают доставку событий.

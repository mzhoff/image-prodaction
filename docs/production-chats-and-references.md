# Чаты Production и обработка референсов

Уточнение владельца от 21 сентября 2026: Production получает собственный список
производственных разговоров — Home, создание изображений, Storyboard и соавтор Flow.
Это дополняет прежнее направление Reverie AI; Notion автоматически не менялся.

## Чаты

В меню под Projects находится сворачиваемая группа «Чаты». При раскрытии она
первый раз загружает пять последних разговоров; «Показать ещё» добавляет следующую
десятку, не уводя пользователя со страницы. Сворачивание сохраняет загруженные
строки в кэше интерфейса. Возврат к уже открывавшемуся фильтру, раскрытие раздела
или всей боковой панели не запускают повторный запрос. Кэш разделён по пользователю,
Workspace, папке и фильтрам; изменения чатов и завершённый ответ ассистента обновляют
соответствующие списки. Детали и проверки — в [описании навигации](./production-navigation.md#sidebar-collections--21-september-2026).
Самостоятельный экран удалён: старый адрес `/chats` переводит на Home. Архив и
корзина доступны через фильтр этой же группы; восстановление остаётся в меню
чата. Показываются личные разговоры пользователя в выбранном Workspace,
а не переписка всех участников. Серверная пагинация ограничена 200 записями за
запрос, порядок — время обновления и ID для одинаковых дат.

Проекты раскрываются в дерево вложенных папок и связанных разговоров. Иконка
разговора показывает текст, изображение, видео, Flow, Storyboard или Timeline.
На строке проекта при наведении/фокусе доступны создание вложенной папки и
переименование. Перетаскивание разговора на проект или папку использует ту же
проверяемую сервером операцию «В проект с материалами»; копий файлов не создаёт.

Беседы Home восстанавливаются по `chat` в URL. Открытие Home, экрана создания,
ассистента Flow, Storyboard или Timeline только читает существующую привязку.
Если её нет, композер работает с локальным черновиком. «Новый разговор» очищает
экран и URL без записи в базу. Документ может существовать без чата, текстовый
чат — без документа.

Первая явная отправка вызывает `POST /api/product-chat/start`: сервер проверяет
сессию, Origin, Workspace и доступ к документу, затем создаёт или восстанавливает
личную привязку. Home использует один ключ начала разговора при повторах запроса;
Flow, Storyboard и Timeline — стабильную привязку пользователя к документу.
Загрузка референсов сама по себе разговор не начинает. События ручных генераций
остаются в журнале документа и переносятся в историю только при наличии чата.
Сообщения, вложения, streaming и retry обслуживает опубликованный ChatModule.

Боковой список, поиск, архив и пагинация выбирают только разговоры с осмысленным
сообщением пользователя (текстом или материалами). До названия от агента используется
первое намерение пользователя; прямое создание видео использует тот же принцип.
Имена документов и стандартные заглушки не считаются названиями разговоров.
Старые пустые записи и события без диалога скрыты, их история не удаляется.

Новая таблица `production_chat` хранит только организацию: название, его источник,
состояние списка и проект. Сервер повторно проверяет владельца, Workspace membership
и принадлежность проекта. Архив и корзина блокируют новые запросы к модели до
восстановления. Они не удаляют документы, изображения или журнал расходов.

«В проект с материалами» выполняется одной транзакцией. Для Flow и Storyboard
меняется папка связанного документа с увеличением revision; открытый редактор
с устаревшей версией получит обычный conflict при сохранении. Медиа Flow/Storyboard
остаются привязаны к своему документу. Результаты генерации Home выбираются
проектом через связь conversation → generation job → asset, включая результаты,
полученные после переноса. Для прямых видеогенераций используется серверная связь
generation job → conversation; открытие чата восстанавливает режим последнего сообщения.
Двоичные файлы не копируются, новые права не выдаются.
Загруженные chat attachments остаются доступными внутри разговора.

Название формируется в обычном, уже учитываемом запросе модели. Модель возвращает
короткое название отдельным служебным тегом перед ответом; адаптер сохраняет его
и удаляет тег до передачи ответа ChatModule. До получения названия используется
начало пользовательского намерения. Отдельного платного запроса нет. Условная
запись не позволяет результату модели перезаписать ручное переименование.

## HEIC и область сброса

Drop overlay находится внутри самой формы и повторяет её контур. Боковая кнопка
типа материала и подсказки не входят в область подсветки. Под формой остаются
только приглушённые ограничения вложений и подсказка Enter. Состояния и ошибки
показываются над композером либо рядом с соответствующим сообщением.

HEIC/HEIF определяется по MIME или расширению, включая пустой MIME из Finder.
ChatModule сразу создаёт карточку в очереди. В ней последовательно видны
«Обработка HEIC…», загрузка и проверка. Ошибка остаётся в карточке с повтором
и пояснением; успешная обработка заменяет заглушку настоящим превью.

`POST /api/chat/v1/references/convert` требует сессию, членство в Workspace и
доверенный Origin. Тело читается с ограничением 8 МиБ. Конвертация выполняется
в отдельном worker thread через libheif-js 1.23.2: до 60 Мп, два одновременных
декодирования, timeout 30 секунд. Результат — WebP до 2048 px без EXIF.
После этого файл проходит обычную загрузку, проверку и хранение ChatModule.
Исходник на компьютере не изменяется. Публичные пакеты ChatModule не форкались.

Использовано [официальное API libheif-js](https://github.com/catdad-experiments/libheif-js).
Для standalone-сборки в `next.config.ts` добавлено явное включение worker dependencies.

## Проверка и локальный запуск

- Миграция `0037_production_chats.sql` применена только к локальной PostgreSQL.
- Транзакционный PostgreSQL-тест проверяет личные чаты, перенос документа и новых
  медиа, отказ чужому Workspace, архив/корзину/восстановление, сохранность артефактов
  и гонку автоматического названия с ручным. Тест завершается rollback.
- Проверены разбор названия, документные вложения, границы выборки медиа и обработка
  настоящего публичного HEIC из тестов libheif-js: получен WebP 1440×960.
- Для HEIC-теста задайте `HEIC_TEST_FILE`; для PostgreSQL — `STORIES_TEST_DATABASE_URL`.
  Эти тесты не обращаются к платной модели.
- `conversation-lifecycle.postgres.test.ts` проверяет открытие всех четырёх типов
  экранов без создания разговора, независимость документов, отложенный перенос
  событий и первую отправку. Запускать с `--experimental-transform-types`
  и `--loader ./scripts/node-test-loader.mjs`; все данные откатываются транзакцией.
- В работающий локальный web добавлена новая HEIC-зависимость без пересоздания
  контейнера. Постоянная установка описана package.json/package-lock.json.
- Ручная браузерная проверка требует входа в приложение: старая сессия недоступна.

Отложено: автоматическое удаление содержимого корзины, общий доступ к личным чатам,
независимые копии переписки и артефактов, семантический поиск по всей переписке.

# Уточнение релиза: пакеты, Timeweb S3 и очистка

22 сентября 2026. Дополнение к [исходному аудиту](./deployment-plan-2026-09-22.md), учитывающее прямые решения владельца. Новый релиз ещё не развёрнут.

## Решения владельца

- Накопленный функциональный объём Production и совместимых зависимостей согласован для подготовки коммитов и деплоя. Это не отменяет проверки состава и исключения секретов/артефактов.
- Старый серверный Production — тестовый, возможен запуск с новой пустой БД без переноса тестовых данных. Новую схему всё равно нужно создать из полного набора migrations. Удаление общей Identity БД не следует автоматически из сброса БД Production: проверить зависимых потребителей и явно определить новый контур.
- Старые неиспользуемые образы для отката этого тестового выпуска хранить не нужно. Данные и резервные копии — отдельная категория.
- Content Hub не нужен в составе этого релиза, его развернут отдельно. Общий ingress/Identity/provider egress нужны Production и не являются лишними только из-за имени `ludimogut`.
- Владелец планирует самостоятельно подключить Timeweb S3 после оценки стоимости; бакет и платные услуги этой задачей не создавались.

## Timeweb S3: подходит по контракту, требуется проверка подключения

Дополнение 22 сентября: подготовлены внешний Compose overlay, проверка вложений,
серверное резервное копирование S3→S3 и локальные тесты. Текущее хранилище не
переключено. Порядок подключения: [external-s3-storage.md](./external-s3-storage.md).
Ниже сохранён первоначальный список подготовки; жёсткий MinIO endpoint в Compose
уже заменён на конфигурируемый, фактический Timeweb probe ещё предстоит.

Timeweb предоставляет [S3-совместимое объектное хранилище](https://timeweb.cloud/docs/s3-storage) с [presigned URLs](https://timeweb.cloud/docs/s3-storage/supported-features/presigned-url). Production уже использует AWS S3 SDK, configurable endpoint/region/bucket и частное хранение; chat attachments работают через S3 adapter ChatModule.

Это отдельная услуга, а не дополнительная папка внутри VPS. Постоянные изображения/видео/аудио/референсы будут в бакете; сервер хранит приложение, БД с метаданными и ограниченные временные файлы обработки. S3 не добавляет оперативную память и не устраняет необходимость дискового резерва под временный видеомонтаж.

Для активной библиотеки предлагается стандартный класс, приватный бакет, 100 ГБ для маленького пилота либо базовые 250 ГБ при ожидаемых видео. Холодный класс — для редко читаемых архивов, не основной библиотеки. Конкретный endpoint и region брать из панели созданного бакета.

### Расчёт по ценам на 22.09.2026

Проверены официальный [калькулятор стандартного S3](https://timeweb.cloud/services/s3-storage) и [правила автомасштабирования](https://timeweb.cloud/docs/s3-storage/manage-storage/s3-autoscaling). Цены с НДС, месячные ориентиры при неизменном объёме, фактическое списание почасовое. Тарифы ранее созданных бакетов могут отличаться.

| Хранимый объём | Хранение в месяц | Расчёт |
| --- | ---: | --- |
| до 100 ГБ | 349 ₽ | пакет 100 ГБ |
| до 250 ГБ | 639 ₽ | базовый объём максимального тарифа |
| 500 ГБ | 1 139 ₽ | 639 + 250 × 2 |
| 1 000 ГБ | 2 139 ₽ | 639 + 750 × 2 |

Исходящий трафик: 100 ГБ/месяц бесплатно на аккаунт, либо 1000 ГБ для Prime; сверх лимита — 1,3 ₽/ГБ. Для расчёта без Prime: `max(0, исходящий_ГБ - 100) × 1,3`. Например, 250 ГБ хранения и 1000 ГБ исходящего трафика ≈ 1809 ₽/месяц; 1000 ГБ хранения и 2000 ГБ трафика ≈ 4609 ₽/месяц. Это только S3, без сервера, AI и отдельного backup-bucket. Бесплатный трафик делится с другими бакетами аккаунта. Повторное чтение/скачивание одного видео также расходует трафик; серверное чтение для обработки не считать бесплатным без проверки условий.

На просмотренном публичном тарифе отдельная ставка за количество API-запросов не указана; не закладывать неизвестный тариф как подтверждённый ноль. Входящий трафик и точные условия конкретного аккаунта проверить в панели при заказе. Платных запросов, заказов и обращения в поддержку в рамках исследования не делалось.

Автоапгрейд 100→250 ГБ не откатывается сам при удалении файлов. На максимальном тарифе превышение 250 ГБ оплачивается по объёму, а при уменьшении объёма снижается только доплата. Поэтому продукту всё равно нужны собственные квоты Workspace и предупреждения о расходе.

### Интеграционные шаги

1. Создать приватный bucket, получить endpoint/region и scoped credentials через защищённое хранилище конфигурации, не через сообщения чата.
2. В Compose overlay задать `S3_ENDPOINT`, `S3_REGION`, `S3_BUCKET`, credentials и подходящий `S3_FORCE_PATH_STYLE` одновременно для web и обоих workers. Сейчас `compose.production.yaml` жёстко задаёт endpoint локального MinIO и path style: одной замены `.env` недостаточно.
3. Согласовать `CHAT_ATTACHMENT_S3_ENDPOINT` и браузерный presigned upload/read endpoint; настроить CORS под домен Production и реально используемые методы/заголовки. Не делать bucket публичным ради загрузки.
4. Убрать зависимость нового запуска от MinIO/init-bucket после переключения. Старый MinIO volume не удалять до подтверждения переноса либо явного сброса именно этих тестовых данных.
5. Проверить put/head/get/range/delete, multipart если используется, signed URL expiry, server seal/copy, checksum, upload через браузер и model delivery через действующий egress. Проверить старые ссылки/metadata при переносе, а не просто сменить endpoint.
6. Подключить lifecycle для staging/temporary/orphan объектов, квоты и ограниченную параллельность временного медиапроцессинга; для постоянных пользовательских assets автоматическое удаление не включать.

Источники в коде: `src/shared/storage/s3-assets.ts`, `src/modules/chat-assistant/server/config.ts`, `server/composition.ts`, `compose.production.yaml`. Реальная совместимость с новым бакетом ещё не проверена: бакет не создан.

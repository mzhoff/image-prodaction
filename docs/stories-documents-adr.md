# Самостоятельные Storyboard и Timeline

21.09.2026. Прямое уточнение владельца заменяет решение первого этапа о двух
представлениях одной записи.

Stories — библиотека двух типов документов. Storyboard хранит blueprint, настройки,
сцены и кадры. Timeline хранит собственный монтаж, пропорции и revision. Оба могут
лежать в общей папке проекта. Timeline может быть самостоятельным либо ссылаться
на Storyboard того же Workspace; одна раскадровка допускает несколько монтажей.
У каждого документа отдельные id, карточка, маршрут и сохранение.

`story_project` сохраняется как хранилище Storyboard; snapshot v2 исключает timeline.
`story_timeline` — самостоятельная таблица. Аддитивная миграция переносит существующий
монтаж в отдельную запись до удаления поля из snapshot, сохраняя исходный JSON v1
в таблице резервных копий миграции. Старые ссылки `?view=timeline` открывают список
связанных монтажей и создание нового. `/stories?view=timeline` фильтрует библиотеку.

Shot id в клипе — необязательная ссылка происхождения. Удаление кадра не удаляет
клип; изменение storyboard не перезаписывает монтаж. Импорт из раскадровки — явное
действие. При смене источника привязки shot очищаются, медиа остаются.

В blueprint слева — сворачиваемый ChatModule с отдельным разговором пользователя
для этой раскадровки. Сервер проверяет доступ и передаёт сохранённый blueprint
в системный контекст. Ассистент помогает обсуждать/писать текст; автоматических
записей в документ и платной генерации медиа в этом срезе нет. Существующие
лимиты, provider ownership и usage остаются в ChatModule/Production.

Создание — визуальные шаги формат → настроение → детали, карточки и chips.
Все меню в изменяемых Stories/Projects поверхностях используют дизайн-токены;
нативные select не используются. Для имени и авторского текста остаётся ввод.

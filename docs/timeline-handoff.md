# Timeline Handoff — согласованный MVP

Решение владельца продукта, 2026-09-06: реализовать одну самостоятельную ноду
обратной раскадровки. Более старые портфельные записи про Stories не отменяют
это явно согласованное расширение scope. Приоритеты в Notion автоматически не меняются.

## Сценарий

1. Подключить `Import.original` (video) к `timelineHandoff.video`.
2. Нажать «Анализ». FFmpeg ищет предполагаемые монтажные склейки; AI не вызывается.
   Во время обработки видны скелетон предпросмотра и общий индикатор процессов,
   который также используется при импорте файлов. Выполненный объём берётся из
   обработки кадров; примерное оставшееся время показывается только после измерения.
3. Проверить планы. Передвинуть общую границу соседних планов, добавить пропущенную
   склейку или убрать лишнюю. Выбрать 1–5 настоящих стоп-кадров каждого плана.
4. Переключать видео/изображения на канвасе или открыть полноэкранную последовательную
   таблицу: медиа и время слева, описание справа.
5. Нажать «Описать этот фрагмент» либо «Создать все описания». Модель анализирует выбранные
   изображения в хронологическом порядке и возвращает краткое описание до 1500 Unicode-символов
   на план. Доступен пресет Simple; другие пресеты не объявлены. Язык по умолчанию — язык приложения.
6. При правке границ, выбранных кадров или ручного текста не запускать модель автоматически.
   Завершённый старый запрос не должен перезаписывать более свежую ручную правку.

План — участок между склейками. Стоп-кадр — одно изображение внутри плана.
Смысловые сцены и группы в MVP отсутствуют. При наплыве предлагается условная граница,
которую пользователь проверяет. Движение камеры или вспышка могут давать ложные склейки.

## Лимиты и обработка

- Исходник до 5 минут, максимум 100 планов и 5 выбранных стоп-кадров каждого плана.
- Порог FFmpeg `threshold` 1–60, default 10. Меньший порог находит больше кандидатов.
- Шесть разрешённых vision-моделей объявлены в `src/shared/api/timeline-models.ts`.
  Доступность у подключённого провайдера проверяется при вызове; цены не зашиты в UI.
- Поэтапные фоновые задачи привязаны к Workspace/document, immutable source/checksum,
  idempotency key и снимку параметров. Описания — платные отдельные вызовы.
- Покадровые правки используют реальные presentation timestamps, включая variable-frame-rate,
  а не приблизительную формулу `номер кадра / средний FPS`.
- Видео при просмотре ограничено границами плана. Для Fragments в режиме selected
  бесплатно подготавливается отдельный видеофайл с точным диапазоном; смена границ
  делает старый файл неактуальным. Оригинал не изменяется. В режиме all Fragments отдаёт
  исходное видео целиком — непрерывную серию всех планов.

## Контракт и переносимость

Авторитетная схема: `src/shared/media/timeline-contracts.ts`, `version: 1`.
`sourceAssetId`, `sourceChecksum`, `durationMs`, реальные `frameTimesMs`, упорядоченные
`shots`. Каждый план содержит `id`, `[startMs, endMs)`, выбранные `frames`
(`timeMs`, optional managed `assetId`), `description`, optional `describedFingerprint`.

Планы покрывают источник без дыр и наложений. Идентификаторы уникальны. Стоп-кадры
принадлежат своему диапазону, поэтому общая граница правится у двух соседей одновременно.
`timelineHandoff.timeline` всегда отдаёт всю раскадровку как JSON. Старые подключения
этого выхода сохраняют прежнюю семантику. `previewMode` меняет только вид просмотра.
Три дополнительных выхода управляются настройкой `outputScope: selected | all` (default selected):

- `videoResult: video` / Fragments: подготовленный клип выбранного фрагмента либо исходное видео всей серии.
- `frames: image` / Frames: галерея всех выбранных кадров указанного объёма, отсортированных по фрагменту и времени. До подготовки всех файлов галерея не считается готовой.
- `descriptions: text`: описание выбранного фрагмента либо описания всех фрагментов, соединённые пустыми строками в исходном порядке.

В selected `activeShotIndex` выбирает результат; в all перелистывание меняет только просмотр.
Смена кадра не переносит старый `assetId` на новое время. Source/checksum и диапазон
в `videoResultSignature` не позволяют отдать старый клип после смены исходника, границ или выбора.
Один провод Frames → Generate Video.reference-1 в режиме references разворачивает галерею
в последовательные слоты. Общий лимит остаётся 3: переполнение, занятые соседние слоты
и частично подготовленные изображения останавливают запрос до платной генерации, без тихого отсечения.
Первый/последний кадр принимают только одно изображение; для галереи используется references.
При создании Generate Video из провода Frames на пустом канвасе Studio сразу выбирает
references, вход reference-1 и совместимую модель из живого каталога. Это работает
также через Router. При недоступном каталоге нода не создаётся; генерация требует
отдельного нажатия пользователем.

Set start/end на курсоре двигает общую границу с соседом. У первого/последнего фрагмента
создаётся недостающий предыдущий/следующий фрагмент, а выбранный original shot ID сохраняется.
Split оставляет выбранный ID слева, Merge with next — у объединённого фрагмента.
Для Output достаточно top-level поля kind json: при публикации его canonical
схема выводится из Timeline-источника, ручные вложенные fields заполнять не нужно.
Публичная проекция (`timeline-public-contract.ts`) отделена от данных редактора:
`source` — video artifact; `shots` — id/startMs/endMs/frameIds/description;
`frames` — id/shotId/timeMs и необязательный image artifact. Стабильные frameIds
явно связывают план с выбранными изображениями. `frameTimesMs` и fingerprints
остаются в snapshot редактора, не раздувают ответы потребителям и не требуют
ослабления общих JSON-лимитов. Для выбранного, но ещё не подготовленного кадра
есть timeMs и источник; отдельный скачиваемый файл не обещается.
При несовпадении подключённого исходника со snapshot старый результат не выдаётся как свежий.

Полные project snapshots сохраняют разбор и managed asset references; доступ к файлам
остаётся Workspace-scoped. Pipeline templates и Favorite сохраняют настройки, но не
разбор чужого видео и не возобновляют старую фоновую задачу.

Executable runtime `timeline.handoff@1` экспортирует **проверенный snapshot**, зафиксированный в pipeline version,
и проверяет соответствие исходного видео. Это не unattended video-analysis capability:
Новые typed outputs закрепляют outputScope и, для selected, индекс выбранного фрагмента
в опубликованной версии. Frames имеет runtime kind image_collection; Graph image-порт
остаётся совместимым с галереями. Старый JSON-only snapshot не зависит от выбора UI.
Новый ролик требует нового разбора/проверки в Studio. Нельзя обещать, что API автоматически
выполнит этап, который в MVP требует решения пользователя.

При публикации сервер проверяет Workspace/status/checksum исходника, а у каждого
подготовленного кадра — operation=timeline_frame, sourceAssetId, sourceChecksumSha256
и точный timelineTimeMs. Для клипа проверяются operation=video_trim, тот же источник/checksum
и metadata.range.startMs/endMs выбранного фрагмента. Серверный assetChecksums фиксируется до вычисления checksum
версии. Runtime повторяет проверки; произвольная картинка или чужой Workspace не
могут подменить выбранный кадр. Автоматическая orphan-cleanup сохраняет файлы,
чьи точные id/checksum закреплены опубликованной версией. Подготовленные файлы
в публичном результате получают защищённые ссылки /v1/runs/.../artifacts/...,
а Runtime v2 выдаёт свои /v2/runtime/runs/.../artifacts/... без storage internals.

## Вне текущего выпуска

Группы сцен, сценарист, генерация фильма, анализ видео со звуком,
подробные Extract-подобные дорожки описаний, экспорт в монтажные редакторы и длинный формат
10–15 минут. Базовые идентификаторы планов и вложенные стоп-кадры оставляют пространство
для этих расширений; не следует имитировать их фиктивными портами или настройками.

## Проверка

Проверить обычную склейку, вспышку без склейки, движение камеры, затемнение, VFR, первый/последний
план, ручное добавление/удаление границы, выбор до пяти кадров, восстановление задачи после
перезагрузки, отказ чужому Workspace, 1500 Unicode-символов, отсутствие перезаписи ручного текста,
независимость JSON от текущей страницы, selected/all typed outputs, галерею одним проводом
в Generate Video references (включая лимит3), возврат раскадровки через Output и отказ при
несовпадении видео. Платный live-запуск проверяется отдельно от fake-provider тестов.

## Ответы на архитектурные вопросы

- Видео → текст поддерживается совместимыми мультимодальными моделями, в том числе Gemini:
  [Google video understanding](https://ai.google.dev/gemini-api/docs/video-understanding),
  [OpenRouter video inputs](https://openrouter.ai/docs/guides/overview/multimodal/videos).
  Прямой видеовход имеет отдельные ограничения провайдера; шесть моделей для выбранных
  изображений не означают, что все шесть принимают видео. MVP передаёт только выбранные stills.
- Python не добавлялся: приложение ставит задачи в существующую очередь, а FFmpeg выполняет
  тяжёлую обработку нативно. Rust-вариант [av-scenechange](https://github.com/rust-av/av-scenechange)
  существует, но авторы ориентируют его на места ключевых кадров кодировщика и предупреждают,
  что это не всегда лучшая детекция человеческих монтажных склеек. Возможная замена требует
  сравнения качества/CPU/памяти на наших роликах, а не предположения о кратном ускорении из-за языка.

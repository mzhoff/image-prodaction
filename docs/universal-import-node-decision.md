# Решение: универсальная нода Import

Дата: 2026-09-06.
Статус: продуктовое решение согласовано владельцем; реализация не начата
в рамках этой фиксации. Документ описывает целевое поведение, а не уже
доступные возможности Studio или Runtime.

## Решение

Развивать существующую ноду `Import` в универсальный вход для файлов.
Не создавать отдельную пользовательскую ноду `Import Audio`: ранее обсуждённое
название обозначает аудиорежим общей `Import`, а не новый пункт палитры.

Файл можно поместить в карточку перетаскиванием или выбрать через загрузку.
После определения его содержимого нода автоматически выбирает представление,
фактический тип выходных данных и цвет коннектора. Выбор определяется файлом,
а не необходимостью заранее выбрать отдельную разновидность Import.

Первое расширение — аудио с сохранением существующего импорта изображений.
Архитектура должна позволять позднее добавить текстовые документы, PDF и
другие явно поддержанные форматы. Универсальность не означает обещание
принимать и исполнять произвольные файлы уже в первом выпуске.

## Внешний вид и типы данных

| Содержимое | Представление Import | Цвет соединения |
| --- | --- | --- |
| Изображение | Превью изображения, существующий сценарий импорта | Синий |
| Аудио | Встроенный плеер, имя файла, длительность и текущая позиция | Отдельный сиренево-фиолетовый цвет аудио |
| Текстовый документ, в будущем | Текстовое представление; детали обработки определяются отдельно | Зелёный для текстового выхода |
| PDF, в будущем | Представление документа; контракт обработки определяется отдельно | По фактическому типу выхода, не по одному расширению |

Цветовая идентификация аудио должна быть общей для всего проекта: точек
соединения, готовых линий и создаваемых связей, а не только карточки Import.
Цвет дополняет тип и его обозначение, но не заменяет проверку совместимости.

При замене файла представление, тип порта и цвет обновляются согласованно.
Существующие связи необходимо перепроверять: смена изображения на аудио не
должна оставлять внешне рабочую связь с нодой, принимающей только изображение.
Способ показа и исправления несовместимых связей уточняется при реализации;
не следует молча превращать аудио в изображение или удалять пользовательский
граф ради смены оформления.

## Аудиоплеер на канвасе

Пользователь должен прослушать импортированную запись непосредственно в ноде:

- запустить воспроизведение и поставить его на паузу;
- видеть текущий тайм-код и полную длительность;
- перемотать к выбранной временной позиции через полосу воспроизведения.

Работа с плеером не должна перетаскивать карточку или панорамировать канвас.
Прослушивание и перемотка — только предпросмотр: они не обрезают исходный файл,
не меняют передаваемую дальше запись и не запускают транскрибацию автоматически.
Ввод тайм-кода отдельным текстовым полем и waveform не являются обязательными
частями этого решения.

## Уточнения для будущей реализации

- Определять реальный контейнер и кодек по содержимому файла, не доверять
  исключительно расширению или присланному MIME.
- Сохранить работоспособность существующих image-графов и неизменяемость
  опубликованных версий pipeline. Техническая миграция типа `importImage`,
  если понадобится, проектируется отдельно.
- PDF не объявлять готовым текстом до определения извлечения текста/OCR и
  выходного контракта. Зелёный цвет относится к текстовым данным, а не
  обещает автоматическое распознавание любого документа.
- Не смешивать импорт/предпросмотр с конвертацией или транскрибацией. Их
  внутренние исполнители и пользовательские настройки согласуются отдельно.
- При реализации одновременно обновить Studio, проверки портов и связей,
  Ask AI, MCP/agent-описания, runtime descriptor/handlers, документацию и тесты
  по инварианту из `AGENTS.md`. До этого не описывать будущие режимы как
  действующие возможности в live-каталоге нод.

## Проверенное текущее состояние, не целевой дизайн

На дату фиксации цвета заданы в
`src/app/styles/node-controls.css`, `src/app/styles/canvas.css` и
`src/widgets/production-canvas/ui/canvas-edges.tsx`:

- image: порт `#001caa`, линия `#052cd9`;
- text: `#16a34a`;
- audio: пока зелёный `#22c55e`.

Таким образом, сиренево-фиолетовый audio — новое согласованное направление,
а не уже существующий цвет. Точный оттенок/семантический токен выбирается при
реализации с учётом различимости: фиолетовые цвета уже используются для
`json` (`#8b5cf6`) и `subject` (`#7c3aed`).

В `src/features/graph-node/ui/nodes/text-to-speech-node.tsx` уже есть локальный
`AudioResultPlayer` с воспроизведением и перемоткой; при реализации проверить
возможность переиспользования, не считать универсальный Import уже готовым.

Эта запись не меняет код, палитру, графы, опубликованные pipeline, приоритеты
или следующий продуктовый рубеж. Записи Notion этой задачей не изменяются.

# Проекты: разные файлы и связанные материалы

## Вложенные папки

Миграция `0038_home_text_and_folder_tree` добавляет nullable `parent_id`:
существующие проекты остаются корневыми, их ID и содержимое сохраняются.
Составной внешний ключ не допускает родителя из другого Workspace. Создавать
дочерние папки можно из строки проекта; существующую папку API не переподчиняет,
поэтому через доступные операции цикл не образуется. При удалении папки её
дочерние папки поднимаются к её родителю, а не удаляются вместе с содержимым.
Системные интеграционные проекты сохраняют прежние ограничения редактирования.

Дерево бокового меню показывает чаты непосредственно в их папке. Перенос чата
на папку сохраняет существующую атомарную операцию переноса связанного документа
и серверные проверки владельца и Workspace.

Реализовано локально 21 сентября 2026 в рамках Home/Flows. Проект-контейнер —
существующая `studio_folder`; Workspace и идентификаторы файлов не меняются.

- `/folders` — список проектов; `/folders/:folderId` — содержимое проекта.
- Старый `/projects/:documentId` остаётся редактором Flow. `/flows?folderId=…`
  остаётся фильтром только Flows, старые ссылки не переопределяются.
- В проекте: Все, Flows, Storyboard, Timeline, Медиа; общий поиск, сетка/список.
  Тип, запрос и вид хранятся в URL.
- Storyboard (`story_project`, snapshot v2) и Timeline (`story_timeline`) —
  самостоятельные документы с разными карточками, URL и revision. Во «Все»
  оба отображаются отдельно. Монтаж может не иметь связи с раскадровкой либо
  ссылаться на одну из доступных раскадровок того же Workspace.
- Доступно создание Flow, Storyboard и Timeline, а также перенос существующего файла в проект.
  Перенос истории сохраняет snapshot с проверкой revision через Stories API.

`GET /api/folders/:folderId/contents?workspaceId=…` проверяет членство и
принадлежность проекта Workspace. Возвращает `stories`, `timelines`, материалы, количество
материалов и курсор следующей страницы (48 объектов).

Связанные медиа — доступные в Library готовые assets активных Flow в папке плюс
references кадров раскадровок и клипов самостоятельных Timeline этой папки. У результата всегда проверяются
Workspace, готовность и видимость в Library; принадлежность не угадывается по
имени. Повторно использованный материал выводится один раз. Аудио отображается
с отдельным типом и открывает существующий авторизованный content endpoint.

Прямое назначение произвольного asset папке не добавлялось: существующая модель
связывает медиа через документы и истории. Загрузка/выбор медиа остаются в
редакторах; проект автоматически собирает их связанные материалы. Медиафайлы не копируются, существующие проекты не мигрируют. Самостоятельные
Timeline используют таблицу и миграцию из модуля Stories. Платных запусков здесь нет.

Проверки: `project-container-items.test.ts` (состав/тип/поиск/Workspace),
`project-media-query.test.ts` (ограничения Workspace, visibility, пустой проект).
Для работающего раздела нужны миграции Stories `0033_story_projects` и `0035_story_documents`.

Папки и документы используют размер карточек Flow: ширина до 420 px, превью
250 px. У папки есть меню открытия и переименования, у Storyboard/Timeline —
открытие, переименование/перемещение, копирование и скачивание JSON. Системные
папки интеграций сохраняют установленное имя.

Уточнение владельца 21.09: [самостоятельные документы](./stories-documents-adr.md).

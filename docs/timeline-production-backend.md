# Timeline: production backend

21.09.2026. Реализация по запросу владельца. Дополнительным решением в этой задаче
включены панель ритма/автомонтажа в Timeline и потоковая загрузка перед закрытой бетой.
Продукт P1, активный фокус, пилот; живая карточка Notion прочитана 21.09.
Текущий рубеж — deployment/общий вход. Изменения локальные, публикация не подтверждена.

## Решение

`story_timeline` остаётся единственным редактируемым документом. OTIO — его
обменное представление, не второй синхронизируемый документ и не журнал событий.
Существующий JSON schemaVersion 1 расширяется необязательными полями; старые
документы читаются без миграции. Legacy PUT сохраняет отсутствующие новые поля.

Производство состоит из отдельных durable jobs: локальная подготовка ритма/ячеек,
явный AI-анализ и предложение монтажа, MP4 render. Очередь, leases, отмена, checkpoints,
Workspace-права и provider usage используют существующий generation worker.
AI не получает права произвольно менять документ: результат — предложение,
применяемое отдельным запросом с expectedRevision. Рендер получает immutable
snapshot. Закреплённые клипы сохраняют положение и диапазон при пересборке.

Timeline Handoff переиспользуется для определения границ и описания фрагментов.
Описание основано на нескольких стоп-кадрах и не доказывает понимания движения.
Музыкальные акценты — оценка сигнала; это не гарантированное определение тактов
или музыкальных частей. Для неопределённого ритма нужен явный BPM/якорь пользователя.
LLM выбирает sourceId/диапазоны из проверенного каталога, а время ячеек вычисляет
детерминированный код. Ответ модели проверяется до применения.

Create/composer используют самостоятельный документ Timeline и параметры promo.
В редакторе появилась вкладка «Промо под трек»: музыка из Library
или загрузка, исходники, brief, длительность, динамика, BPM и положение первого удара.
Ритм и AI запускаются разными кнопками. Можно добавить загруженное/сгенерированное
аудио, менять его диапазон и громкость, закреплять клипы, подготовить и скачать MP4.
Произвольный опубликованный Flow автоматически не запускается: будущая интеграция
использует pinned capability. Чат Timeline консультирует, задания запускает пользователь.

## Границы первого обменного профиля

Одна последовательная видеодорожка (видео/изображения), отдельные аудиоклипы,
обычные склейки, FPS и монтажные диапазоны. OTIO импорт не загружает файлы по URL:
каждая media reference явно сопоставляется с доступным ассетом Workspace.
Неизвестные эффекты, переходы, retiming, вложенные композиции и неподдерживаемые
дорожки отклоняются, а не теряются молча. Проверка в CapCut/Premiere/Resolve — позже.

Приоритет результата: MP4 для скачивания. OTIO import/export — backend API и
проверка формата; это не заявление о подтверждённом обмене с конкретным редактором.

Лимит исходного видео — 1 ГиБ. HTTP multipart разбирается потоком во временный файл,
S3 принимает файловый поток; фоновый worker проверяет исходник и строит превью.
Скачивание исходника из S3 и передача FFmpeg также используют файл, без полного
буфера видео в JavaScript. Производные видео/MP4 остаются ограничены 128 МиБ.
Подробный контракт загрузки и ограничения: [Streaming media](streaming-media-and-rhythm.md).

## HTTP-контракт для будущего Create и Timeline Redactor

Все операции требуют сессию и доступ к Workspace. Изменяющие запросы требуют
доверенный `Origin`; JSON ограничен 2 МиБ. `409 revision_conflict` требует
перечитать документ. Передача чужого assetId не даёт доступа к его содержимому.

| Endpoint | Назначение |
| --- | --- |
| `POST /api/stories/timelines/create` | Атомарно создать документ с новым проектом либо связать с существующим |
| `GET/PUT /api/stories/timelines/:id` | Читать/сохранить монтаж; существующий контракт расширен аудио и параметрами производства |
| `POST /api/stories/timelines/:id/jobs` | Запустить `rhythm`, `plan`, `render` или отдельный `analyze`, ответ 202 с job/statusUrl |
| `GET/DELETE /api/stories/timelines/:id/jobs/:jobId` | Статус, промежуточный/готовый результат, отмена |
| `POST /api/stories/timelines/:id/jobs/:jobId/apply` | Применить готовое предложение: `{ "expectedRevision": N }` |
| `GET /api/stories/timelines/:id/jobs/:jobId/download` | Скачать MP4 успешного render, поддержаны Range и attachment |
| `GET/POST /api/stories/timelines/:id/otio` | Скачать OTIO / импортировать поддерживаемый профиль в документ |

Создание: `{ workspaceId, name, project, snapshot }`. Проект —
`{ mode: "existing", folderId }` либо `{ mode: "new", name }`. Исходники из
`production.sourceAssetIds`, видео и аудио из монтажа видны в составе проекта
через связь с документом. Неуспешная проверка исходников откатывает создание папки.
Для черновика до загрузки файлов можно передать snapshot без `production`.

Новые необязательные поля snapshot:

- `frameRate`: 24/25/30/50/60, при отсутствии 30;
- `production`: `{ purpose: "promo", brief, targetDurationMs, pacing, sourceAssetIds }`;
  pacing — `calm`, `normal`, `dynamic`, `mixed`;
- `audioTracks`: необязательные именованные дорожки `{ id, name }[]`, включая пустые;
- `audioClips`: `{ id, assetId, startMs, sourceInMs, durationMs, gain, role?, trackId? }[]`;
  role — `music`, `voice`, `effect`, gain 0–2;
- `sourceAudioGain`: громкость звука исходных видео, 0–2;
- `lockedClipIds`: клипы, которые модель не должна переставлять/перерезать.

Уже загруженное или сгенерированное аудио используется через обычный assetId.
Загрузка файлов остаётся в существующих `/api/assets/video` и `/api/assets/audio`.
Аудио внутри видео сначала выделяется существующей video-derive операцией.
Пустой `audioClips: []` явно очищает звук; отсутствие поля в старом клиенте
сохраняет текущие дорожки. Укорочение монтажа, оставляющее аудио за его границами,
отклоняется: фронтенд должен явно предложить пользователю обрезку аудио.

Каждый jobs-запрос содержит `idempotencyKey` и `expectedRevision`:

```json
{
  "action": "rhythm",
  "idempotencyKey": "one-logical-grid",
  "expectedRevision": 0,
  "musicAssetId": "<audio asset UUID>",
  "musicSourceInMs": 0
}
```

`rhythm` не принимает модель и не запрашивает provider credential. Необязательные
`bpm` (40–240) и `beatOffsetMs` задают ручную сетку; `previousGridJobId` позволяет
использовать готовую энергию того же музыкального диапазона при поправке BPM.
Результат `kind: grid` содержит `music` и `slots`. Документ/видеоклипы не изменяются.
Длины варьируются: calm около 4–6 секунд, normal 2–4, dynamic 0,5–2; mixed выбирает
характер по энергии. Границы привязываются к ударам, а в динамичных частях — также
к полудолям. Последняя ячейка, граница закреплённого клипа и длинное действие могут
отличаться от предпочтительного диапазона. Это не жёсткий метроном.

`plan`: `{ action: "plan", idempotencyKey, expectedRevision, model, gridJobId,
analysisJobId?, slots? }`. Нужна успешная сетка для той же ревизии и snapshot; BPM здесь
менять нельзя. Сетка больше 100 ячеек отклоняется до оплаты. Модель из каталога
`TIMELINE_MODEL_OPTIONS` сначала описывает сцены, затем выбирает фрагменты. Готовый
каталог из прежнего analyze/plan переиспользуется при совпадении исходников и checksum;
изменение длительности/музыки не требует описывать видео заново. AI может объединить
до трёх соседних свободных ячеек через `throughSlotId`, сохранив непрерывное действие,
но не пересекать закреплённые клипы. Результат содержит `snapshot`, `slots`,
`analysis` и объяснения в `reasons`; документ меняется только после отдельного apply.
Старый саундтрек с role=music заменяется, остальные аудиоклипы сохраняются.
Если сохранённое аудио больше новой длительности, предложение отклоняется.

`render`: `{ action: "render", idempotencyKey, expectedRevision }`. Музыка не
обязательна. Рендер идёт по снимку документа на момент запроса. Изменения после
запуска не меняют уже запущенное видео; результат содержит исходную revision
в метаданных ассета. Выход — обычный video asset, видимый в Library.

Импорт OTIO: `{ expectedRevision, document, bindings }`, где `bindings` — объект
`target_url -> { assetId, kind }`. Ссылки никогда не загружаются автоматически.
Экспорт по умолчанию содержит `asset://<UUID>`, без подписанных ссылок/токенов.
Медиафайлы в `.otio` не упакованы; для стороннего редактора понадобится relink
или отдельная будущая упаковка исходников. Громкость/роли/locks хранятся в
`metadata.reverie`; перенос этих параметров сторонними редакторами не подтверждён.
Формат сверялся с [официальной схемой OTIO](https://opentimelineio.readthedocs.io/en/latest/tutorials/otio-serialized-schema.html).

## Ограничения и проверка

- Promo: 5–180 секунд; до 20 исходников, каждый до 5 минут, суммарно до 15 минут;
  до 60 сцен. Проверка числа сцен происходит до платных описаний.
- До трёх настоящих кадров на описание сцены. Один платный запрос на сцену и
  один на подбор монтажа. Повтор использует checkpoints/idempotency;
  неопределённый результат платного вызова не отправляется автоматически снова.
- Алгоритм музыки: FFmpeg → mono PCM 8 кГц → огибающая/onsets → автокорреляция
  темпа и локальные акценты. Это базовый оценщик, без определения downbeat,
  куплетов/припева и без обещаний точности для свободного/меняющегося темпа.
- Рендер: 1–100 клипов, до 5 минут, до 32 аудиоклипов, 720p, H.264/AAC, до
  128 МиБ. Частота кадров фиксированная; границы округляются накопительно,
  с точностью одного выходного кадра. Изображения до 40 мегапикселей вписываются
  с полями; анимированные изображения используются как неподвижный первый кадр.
- FFmpeg/ffprobe нужны существующему worker; рендер проверен на FFmpeg 6.1.1.
  Старые сборки без `alimiter latency` не поддерживаются. Dockerfile уже
  устанавливает FFmpeg; новый сервис, Python runtime и миграция БД не добавлены.
- Временные файлы ограничены, удаляются после работы/отмены; декодирование
  последовательное внутри задачи, общий существующий лимит — два обработчика.
  Лимит исходника 1 ГиБ не заменяет нагрузочный тест production по памяти и диску.
- Автоочистка сохраняет ассеты документа и незавершённых/успешных montage jobs.
  Явное удаление исходника пользователем по-прежнему делает его недоступным.

Подтверждено локально 21.09.2026: синтетический MP4 со склейками и смещённой
музыкой; сохранение исходного звука; 20 коротких клипов без накопления ошибки
длительности; два параллельных рендера без зависания. Официальная Python-библиотека
OpenTimelineIO 0.18.1 прочитала экспорт и выполнила обратную сериализацию.
PostgreSQL-проверка прошла в транзакции с полным откатом тестовых записей.
Покрыты права, диапазоны, atomic create, CAS, retention, отмена, восстановление
после сбоя checkpoint, неизменность исходников и защита закреплённых клипов.

Live-вызовы платной модели, художественная оценка на пользовательских видео,
production-нагрузка и импорт в CapCut/Premiere/Resolve пока не проверены.
Запуск опубликованного pipeline из promo остаётся отдельной будущей интеграцией.
Браузерный предпросмотр использует HTML audio/video и синхронизацию по playhead;
его точность не равна кадровой точности FFmpeg-рендера.

Первый backend-прогон до расширения потоковой загрузки: 74/74 теста, без пропусков. `typecheck`, `lint`,
`check:architecture`, `check:size`, `git diff --check` прошли. Тестовые codec/SDK
инструменты удалены из временной папки (фактически освобождено около 123 МиБ).
Для повторения codec-проверок нужны `FFMPEG_PATH`, `FFPROBE_PATH` и
`VIDEO_CODEC_TESTS_REQUIRED=1`; для SDK — `OTIO_PYTHON` и при необходимости
`OTIO_PYTHONPATH`, для БД — `STORIES_TEST_DATABASE_URL` локального тестового контура.
Проверки расширения и актуальный сценарий UI перечислены в [Streaming media](streaming-media-and-rhythm.md).


UI автосохранения и экспорта (21.09.2026): Timeline ведёт локальный журнал и
последовательную очередь существующих PUT с expectedRevision; новых API и
миграций не требуется. Кнопка «Экспортировать» в шапке дожидается синхронизации
перед render. OTIO из меню строится существующим pure core экспортером из
текущего локального snapshot, содержит asset:// и не включает исходники.
Это не экспорт нативного проекта CapCut/Premiere/Resolve. Подробности и
сценарии восстановления: [Timeline viewport](./timeline-viewport.md).

### Дополнительные видеодорожки

Snapshot v1 расширен необязательными `videoTracks` (до 15) и парой `trackId/startMs` у клипа. Без них клип остаётся в основной последовательности. Внутри дополнительной дорожки запрещены пересечения; длительность документа определяется последним концом клипа, а не суммой всех слоёв. Слои выше основной перекрывают её целиком; исходный звук следует за видимым кадром. Предпросмотр и render используют `timelineVideoSegments`; renderer принимает до 200 видимых отрезков для прежнего лимита 100 исходных клипов и пяти минут. Пустоты кодируются чёрным с тишиной. OTIO сохраняет дорожки и gaps; все внешние ссылки требуют прежней явной привязки к ассетам Workspace. Старые записи без `videoTracks` сохраняют существующие дополнительные слои. AI меняет только основную последовательность.

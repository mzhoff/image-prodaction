# Организация Library и проектов

## Согласованный запрос, 10.09.2026

Library и My Files имеют отдельные ссылки на раздел и шевроны раскрытия.
Library содержит изображения, сохранённые пайплайны, персонажей и группы по
проектам. My Files содержит все канвасы и проекты-папки; внутри проекта доступны
те же фильтры, карточки и список. Адреса существующих `/projects/<documentId>`
не меняются: это канвасы, не новые папки.

## Границы реализации

- Папка проекта принадлежит Workspace. На первом уровне один канвас может
  находиться в одной папке либо без папки. Группировка не меняет snapshot графа,
  IDs нод, опубликованные версии или права доступа.
- Library проекта выбирает материалы его канвасов по сохранённой связи, а не
  угадывает принадлежность по имени «Content Hub». Исторические канвасы не
  перекладываются автоматически.
- Сохранение канваса в Library — явная отметка для повторного использования,
  не публикация Runtime endpoint. Существующий каталог опубликованных
  executable pipelines остаётся отдельно в Pipelines.
- Персонаж использует существующий SubjectPassport: имя, тип, описание,
  неизменные признаки, изменяемые атрибуты, ограничения, заметки и изображения.
  Форма и Subject Builder читают/сохраняют одну серверную сущность с проверкой
  Workspace и версии. Использование на канвасе — редактируемый снимок паспорта,
  не живая подписка на чужие изменения. Старые локальные паспорта сохраняются;
  публикация переносит их в общую библиотеку только по действию пользователя.
- Проектные папки и паспорта — ответственность Studio, не Control Plane, CMS,
  Identity или новый Media Service. Платные генерации остаются явными действиями
  существующего production workflow. Новые сервисы и провайдеры не нужны.

## Контекст

Прочитана текущая карточка продукта Notion (обновлена 31.08.2026): P1, активный
фокус, пилот. Принятое решение 27.08 — Stories и 20 повторяемых запусков pinned
pipeline. Данный запрос владельца расширяет организацию Studio, но сам по себе
не закрывает этот эксперимент. Рыночный тезис о стоимости моделей не является
основанием запускать платные генерации при сохранении или открытии библиотеки.

## Миграция и совместимость

Миграция `0027_sturdy_blue_blade.sql` добавляет `studio_folder`, `subject_profile`,
`document.folder_id`, `document.library_saved`. Связь папки проверяется сервером
и составным внешним ключом Workspace + folder. Сохранённый в Library или
помещённый в папку пустой канвас не удаляется как случайно открытый черновик.

Добавления аддитивные. Нельзя автоматически копировать локальные subject-записи
между пользователями, перезаписывать канвасы или менять опубликованные pipelines.
Перенос между папками не изменяет revision графа.

## Как использовать

1. Раскрыть My Files → Проекты → Новый проект. Например, «Content Hub».
2. В меню канваса выбрать «Переместить в проект». Внутри папки доступны поиск,
   избранное, карточки/список, создание канваса и переход к графике проекта.
3. Library → По проектам → папка показывает изображения и видео, сохранённые
   в Library из её активных канвасов. Принадлежность вычисляется через documentId;
   после перемещения новые и старые материалы отображаются в новой папке.
4. «Сохранить в библиотеку» в меню канваса добавляет его в Library → Пайплайны.
   Это ссылка на текущий канвас, не замороженный шаблон и не опубликованный API.
5. Library → Персонажи → Создать персонажа: имя, тип, сохранение идентичности,
   описание, постоянные/изменяемые признаки, ограничения, заметки, до 24 картинок.
   Имя до 120 символов, каждое большое поле до 10000. Загрузка сохраняет оригинал
   и серверную миниатюру штатным сервисом изображений.
6. «Открыть в Subject Builder» сохраняет паспорт и создаёт заполненный канвас,
   не вызывая AI. Generate Description / Canonical references работают в ноде;
   в форме их платные вызовы не дублируются. Publish Subject / Update Library
   возвращает изменения в общий каталог; Load явно загружает паспорт в другую ноду.

Форма предупреждает о несохранённых правках. Сохранение проверяет `expectedRevision`:
конкурирующая старая версия получает 409, а не затирает новый паспорт. Каталог
загружает краткие карточки без всех больших текстов; полный паспорт — при открытии.
Паспорта, ранее сохранённые только в `graph.subjects`, остаются доступными в ноде
и переносятся на сервер по Publish/Update, без скрытой массовой миграции.

## Проверки

`e2e/library-organization.spec.ts` проверяет реальные формы, меню, загрузку
референса, round-trip формы/ноды, неизменность snapshot/revision при группировке,
изоляцию Workspace, конфликт версий и удаление только папки без удаления файлов.
AI-запросы в браузерном сценарии блокируются; платная генерация не требуется.

Локальная проверка 10.09.2026:

- Миграция применена, production-сборка Next.js успешна.
- Полный набор unit-тестов: 845 пройдено, 10 пропущено, ошибок нет.
- Typecheck, lint, architecture и `git diff --check` пройдены.
- Browser E2E: организация Library и общий паспорт (включая 768/375 px),
  переиспользование изображения/буфер обмена/доставка в канвас, галерея с
  пропорциями и датами, 20 повторных mouse-flick на основном слайдере и миниатюрах.
- Живая read-only проверка Content Hub Runtime v2: connection verified,
  7 grants, 5 pipelines; платных запусков не было.
- Общий `check:size` остаётся красным из-за пяти ранее изменённых файлов за

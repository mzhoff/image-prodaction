# Library: исправления мыши и наложения карточек

Проверено 10 сентября 2026 года на локальном Image Production через
`http://127.0.0.1:7310`. Это проверка локальной сборки, не публикация в production.

## Исправленные причины

1. Обратное движение мыши на 1–2px перед отпусканием считалось новым разворотом
   и удаляло историю скорости всего свайпа. Теперь такой микровозврат не меняет
   направление импульса; настоящий разворот подтверждается при 3px суммарного
   обратного движения. Это не порог начала драга: движение на 1px по-прежнему
   запускает его. Удержание на месте 300мс снимает импульс, как и раньше.
2. Стрелки перехватывали начало перетаскивания. Теперь область стрелки также
   принимает драг, а следующий за ним клик подавляется. Обычный клик и Enter
   переключают изображение, в том числе во время инерции.
3. Основной просмотр создавал одно окно карточек, а координаты рассчитывались
   для другого. У краёв списка лишние карточки оставались в центре, в полном
   размере. Теперь отрисовка и расчёт используют общий диапазон до 9 карточек.
   При смене диапазона карточка без готовых координат скрыта, а не накрывает соседей.

Не менялись коэффициенты инерции, свободная остановка без привязки к центру,
путь событий wheel/трекпада, загрузка оригиналов и резервирование места для
метаданных/кнопок. Высокочастотные данные жестов остаются в refs, без новых
обновлений React-состояния на каждом движении мыши. Контракты нод и MCP не менялись.

## Проверки

- До обновления новый `e2e/library-mouse-regression.spec.ts` воспроизвёл оба
  дефекта: потерю инерции при микровозврате и видимые карточки без transform.
- После обновления прошли все 7 сценариев Chromium:
  - `library-mouse-regression.spec.ts` — 2 сценария: 20 повторных свайпов мышью
    на каждой из двух лент, микровозврат перед отпусканием, разгон, драг из
    областей обеих стрелок, клик во время инерции, Enter и события wheel;
    все карточки позиционируются у краёв, при драге и на узком экране.
  - `library-motion-recovery.spec.ts` — 3 сценария: пагинация, прерывания,
    последовательный разгон и торможение.
  - `library-dock.spec.ts` — 1 сценарий: синхронизация лент, однопиксельный драг,
    свободная инерция, явный выбор, клавиатура, touch и Reduce Motion.
  - `library-viewer-layout.spec.ts` — 1 сценарий: задержанная загрузка оригинала,
    пустые/длинные метаданные, смена изображений, широкое и узкое окно.
- В первой серии последние 2 сценария встретили HTTP 429 при создании тестовых
  аккаунтов. После истечения окна ограничения оба прошли без изменения лимитов
  авторизации. Повторный запуск: 2 passed (22.1s).
- `npm test`: 839 passed, 10 skipped, 0 failed (849 всего).
- `npm run typecheck`, `npm run lint`, `npm run check:architecture` — пройдены.
- Docker production-сборка web — пройдена.
- Проверки используют отдельные QA-аккаунты и изображения-заглушки. Платные
  запросы генерации заблокированы. Это автоматизированные pointer/wheel-тесты,
  не утверждение о ручной проверке физической мышью или трекпадом.

Команда браузерной проверки (при большом количестве QA-регистраций разбить на
серии с учётом ограничения авторизации):

```sh
PLAYWRIGHT_BASE_URL=http://127.0.0.1:7310 npx playwright test \
  e2e/library-mouse-regression.spec.ts e2e/library-motion-recovery.spec.ts \
  e2e/library-dock.spec.ts e2e/library-viewer-layout.spec.ts --workers=1
```

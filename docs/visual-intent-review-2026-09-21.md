## Доработка общего входа

Изменения общего протокола сделаны в исходном репозитории Content Hub / Identity,
а не внутри установленной зависимости. В продукт подключён точный архив
`@reverie/identity-client@0.1.0-canary.7`; архив разрешён для хранения в Git.
Контрольные суммы установленного клиентского модуля, исходной сборки и архива совпали.
Договорённость записана в upstream ADR `docs/adr/2026-09-21-embedded-telegram-login.md`.

SDK хранит доказательство Telegram-попытки и параметры OIDC на сервере, требует
явного согласия с условиями для нового аккаунта и не принимает повторный запрос
завершения. Временная Identity-сессия удаляется после обмена и ограничена 60 секундами.
Отмена очищает текущую попытку, текущую сессию продукта и текущую браузерную
Identity-сессию через привязанный к браузеру переход. Другие устройства сохраняют вход.
Встроенный сценарий сам не устанавливает браузерную SSO-cookie Identity.

Добавлены русские и английские подписи новых состояний. До согласия кнопка
«Продолжить» выключена. На шаге условий верхняя кнопка заменяет старую ссылку;
вторая дублирующая кнопка внутри карточки не выводится.

## Проверки и границы

- Typecheck, ESLint и проверка архитектуры Image Production прошли.
- 23 теста продукта: онбординг, политика авторизации/сессий и каталог переводов.
- 8 тестов общего SDK прошли.
- 24 теста Identity прошли; после добавления проверки истечения срока повторно
  прошли все 4 теста встроенного входа. Проверены OIDC, Origin, browser proof,
  обязательность согласия, повторный запрос, отмена, сохранение других сессий,
  изоляция лимитов посетителей за доверенным proxy и истечение попытки.
- Сборки SDK и Identity, адресная проверка Biome прошли.
- Локальные Identity и web перезапущены. Readiness успешен; из Content Hub
  проверены авторизованные чтения Runtime v2 client/grants для существующего
  подключения. Генерации не запускались.
- Временная сессия синтетического пользователя для проверки онбординга удалена.
  Реальные пользовательские аккаунты, материалы и другие устройства не сбрасывались.
- Браузерная проверка покрывает запуск/ожидание/отмену и отображение согласия.
  Подтверждение Telegram тестировалось на изолированной фикстуре с обработчиком
  бота, без отправки сообщений реальному пользователю. Полный вход через живого
  Telegram-бота остаётся ручной интеграционной проверкой.
- Production не развёртывался. Перед релизом Identity необходимо обновить раньше
  потребителя и проверить доверенные IP reverse proxy, как описано в
  `docs/identity-integration.md`.

Статусы задач исправляются через API Visual Intent с проверкой revision.
Исторический результат исходного неуспешного запуска сохраняется: это не новый
запуск worker и не подмена его отчёта. Восемь проверенных задач имеют статус `applied`.
Финальное чтение API подтвердило: в исходном пакете все 24 задачи имеют статус
`applied`; во всём проекте задач со статусом `rejected` не осталось.

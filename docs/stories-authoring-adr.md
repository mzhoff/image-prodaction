# ADR: Stories authoring в Production

Уточнение 21.09: добавлен [этап подготовки героев](story-character-passports.md)
и инструмент `story_save_characters`. Визуальные переключатели и агент меняют
общий JSON-паспорт; сервер производит промпт из этого паспорта. Паспорта остаются
в snapshot Stories, генерация использует существующую очередь Generation.
Новых границ сервиса и отдельной копии ChatModule нет.

Уточнение 21.09: модель двух представлений заменена [отдельными документами](stories-documents-adr.md). Ниже сохранено исходное решение первого этапа.

21.09.2026. Статус: локальное решение для первого этапа прямого запроса владельца.

Production получает раздел Stories и два представления одного проекта:
storyboard и простой монтаж. Полный [план](stories-production-plan.md) сохраняет
все дальнейшие этапы. Это расширяет прежнюю UI-границу из решения 17.09;
глобальное владение Stories между Production и Reverie AI пока не меняется.

Первый этап — отдельный модуль `src/modules/story-projects` и таблица
`story_project`: Workspace, папка, автор, revision и JSON с blueprint/сценами/
кадрами/монтажом. Сервер проверяет membership, папку и материалы того же Workspace.
Сохранение использует сравнение revision; конфликт не перезаписывает чужие правки.
Существующие documents, Workspace IDs, Stories slides и Timeline Handoff не меняются.

Причина: авторская история имеет смысл без графа и без запущенной генерации.
Хранение её в canvas snapshot смешало бы сценарий с технической реализацией рецепта.
Отдельный модуль позволяет подключить AI-adapter позднее без второго сценария.

Первый монтаж — последовательность выбранных image/video ассетов на одной дорожке,
с порядком и диапазонами. Это основа простого черновика; несколько дорожек,
микрофон, рендер и внешний экспорт остаются этапами плана. Ассеты не копируются,
не удаляются и не перегенерируются при изменении истории. Удалённый из Library
исходник должен отображаться как недоступный; retention для публикации/render
snapshot проектируется в S3/S4 отдельно.

Миграция аддитивна. Её доставка идёт через существующий migration pipeline;
откат кода не требует удаления историй. Экспорт JSON — резервная копия авторского
документа, не видео и не проект CapCut/Premiere/DaVinci.

Перед подключением Reverie AI: согласовать канонического владельца, API/revisions,
asset access и совместимость контрактов с центральной архитектурой. До этого
нет прямых межпродуктовых DB-записей, новых service tokens и изменения grants.


## Структурированное соавторство (21.09.2026)

Внутри существующего продуктового adapter ChatModule добавлены `story_ask_question`, `story_save_blueprint` и `story_create_scenes`. Идентичность и история диалога остаются в ChatModule; содержание blueprint/scenes и CAS-ревизии остаются в Stories. Нового сервиса или отдельной копии ChatModule нет.

Чат может подготовить запись только в документ, связанный с разговором на сервере. Клиент передаёт revision как контекст, сервер проверяет её при подготовке, а при исполнении выполняет CAS. Подписанный write-tool исполняется автоматически только в активном интерфейсе автора без несохранённых правок. Отмена останавливает ещё не подтверждённые действия этого хода. Подробности сценария и проверки — в `docs/home-storyboard-creation.md`.

# Локальная проверка первого входа

21 сентября 2026. Реализован первый срез из
[плана](first-user-onboarding-plan-2026-09-21.md); это не production-релиз.

## Как пройти

1. Для полной проверки выйти из текущего продуктового аккаунта и открыть
   `http://127.0.0.1:7310/login` (Visual Intent) либо `http://localhost:3004/login`.
   В пределах одного прохода не менять адрес: у `localhost` и `127.0.0.1` разные cookies.
2. Нажать Telegram, подтвердить вход в **@reverie_local_test_bot**, вернуться
   в исходную вкладку. Telegram подтверждает сам пользователь.
3. Новый аккаунт открывает `/onboarding`: имя, возраст и роль → рабочий контекст →
   цели → задачи → опыт. На последнем шаге можно отметить ChatGPT, Claude / Claude Code,
   Antigravity, Codex, Cursor, другие инструменты или отсутствие опыта.
4. Ответы сохраняются автоматически; переход между шагами ждёт подтверждения сервера.
   Можно обновить страницу или выйти и войти заново — анкета продолжится с сохранённого шага.
5. После завершения открывается исходная безопасная страница или Home. У Home есть
   тур по боковому меню, переключателю продукта, шапке, композеру и кнопке помощи.

Для просмотра без изменения серверной анкеты:
`http://localhost:3004/onboarding?preview=1` — требуется действующий вход.
Черновик просмотра хранится только в текущей вкладке. Язык и тема визуально применяются
к браузеру; preview не создаёт пользователя, Workspace, чат или материалы.

## Данные и поведение

- `user_onboarding` принадлежит продуктовому аккаунту; связь с Identity не меняется.
- RU/EN и светлая/тёмная/системная тема доступны в анкете.
- На сервере проверяются обязательные ответы, размер запроса, аккаунт и ревизия.
  Устаревшая вкладка получает конфликт, а не перезаписывает новые ответы.
- Уже существовавшие пользователи отмечены `legacy_exempt`; им не приписано
  прохождение анкеты и не заблокирован рабочий кабинет.
- Сохранённые предпочтения из анкеты импортируются в браузер один раз на ревизию,
  чтобы последующая смена темы в меню аккаунта не откатывалась при обновлении.
- При первом автоматическом пропуске многошагового тура появляется указатель на «?».
  Одношаговые подсказки закрываются без него и отмечаются показанными.
  После ручного открытия и пропуска любого тура указатель не повторяется.

## Проверки и границы

- Unit: обязательные и условные ответы, нормализация, исключающий вариант «Пока
  не использую», допустимые коды и ограничения API.
- Live HTTP + PostgreSQL: синтетический локальный аккаунт, вход, обязательный
  redirect, сохранение, выход/повторный вход, восстановление шага, конфликт ревизий,
  запрет чужого account ID, завершение и открытие кабинета. Временные данные удаляются.
- Браузер: пять экранов preview, восстановление после reload, множественный выбор
  агентов, RU/EN, завершение, все пять targets Home, ручной пропуск без повторного указателя.
- TypeScript, ESLint, архитектурные границы и лимиты файлов проверяются отдельно.
- Живое подтверждение Telegram остаётся пользовательской приёмкой. Синтетический
  вход не доказывает доставку сообщений ботом или завершение OIDC реальным пользователем.
- Серверное сохранение прогресса относится к анкете. Состояние туров пока сохраняется
  существующим механизмом в localStorage, отдельно для пользователя и раздела.
  Адресные маски остальных экранов и синхронизация туров между браузерами — следующий срез.

## Локальный сброс Telegram для повторной регистрации

По прямому запросу владельца освобождена его привязка Telegram в локальной базе
`reverie_identity`. Строка прежнего пользователя сохранена, сеансы этого Identity
закрыты, незавершённый challenge отменён. Идентификатор Telegram и исходная связь
сохранены в защищённом recovery-файле вне Git (`~/Library/Application Support/Reverie/identity/recovery/`).
Проектные базы, владельцы Workspace, токены ботов, webhook и production не менялись.
Новая Telegram-регистрация создаст отдельный тестовый аккаунт; старые проекты
автоматически к нему не переносятся.

Проверка PostgreSQL-теста (локальные `.env` загружаются без вывода секретов):

```sh
RUN_ONBOARDING_POSTGRES=1 node --env-file=.env --env-file=.env.local \
  --experimental-strip-types --loader ./scripts/node-test-loader.mjs \
  --test src/modules/user-onboarding/server/onboarding.postgres.test.ts
```

# Приватные пакеты: локальный доступ

Для установки используется отдельный GitHub-токен только с `read:packages`.
Он не разрешает публикацию, удаление пакетов или доступ к исходникам private repos.

## Сохранение на macOS

Запустить команду **без значения токена после `-w`** и вставить токен в скрытый
запрос пароля (повторить при запросе подтверждения):

```sh
security add-generic-password -U -a mzhoff -s codex.image-prodaction.github-packages -w
```

`-U` заменит только локальную запись с этой парой account/service, если она уже есть.
Сам секрет не передаётся в аргументах команды, не попадает в историю shell и Git.
Не использовать `security find-generic-password ... -w` отдельно: эта команда
выводит секрет в терминал. Установщик забирает её вывод напрямую в память.

## Проверка и установка

```sh
npm run packages -- check
npm run packages -- view @prodactionpro/chat-ui@0.12.0 version
npm run packages -- ci
```

Для изменения зависимостей: `npm run packages -- install <package>@<exact-version>`.
UI-пакеты обновляются совместно на одну проверенную exact-версию. `ci` удаляет
нынешний `node_modules` и ставит только lock-файл: не запускать его поверх ещё
не опубликованной локальной tarball-интеграции.

Скрипт проверяет права токена, читает конкретную запись Keychain и передаёт секрет
только в окружение дочернего npm. `scripts/private-packages.npmrc` хранит лишь
ссылку на переменную, не секрет. Пользовательский `~/.npmrc` не изменяется.
Lifecycle scripts зависимостей и debug-файлы npm отключены. Если пакету нужен
`rebuild`, его выполняют отдельно после проверки, без окружения с токеном.

В CI можно передать `PRODACTION_PACKAGES_READ_TOKEN` из защищённого хранилища:
эта переменная имеет приоритет над Keychain. Скрипт не создаёт и не меняет CI secrets.
`publish`, `config`, `exec`, `run` и другие неустановочные команды запрещены обёрткой.

## Граница готовности

Успешный `check` подтверждает доступ к registry; он отдельно показывает наличие
подготовленной Reverie-версии. Доступ на чтение не публикует отсутствующие версии.
Порядок поставки UI описан в [UI-контракте](./reverie-ui-contract.md).
Docker продолжает использовать существующий BuildKit secret `npm_token` через
`compose.private-packages.yaml`; сам токен нельзя записывать в Compose или `.env`.

При поставке Reverie 2026-09-10 роли разделены: запись
`codex.image-prodaction.github-packages` (account `mzhoff`) содержит токен только
с `read:packages`; отдельно сохранён публикующий токен в
`codex.image-prodaction.github-packages.publish`. Установщик не читает вторую
запись и отклоняет токены с расширенными правами. У публикующего токена сейчас
`repo, write:packages`: право `repo` для этой публикации не использовалось;
его последующее сужение или отзыв — отдельное решение владельца.

Dockerfile передаёт токен из BuildKit secret в окружение только текущего шага
установки. Временная npm-конфигурация содержит ссылку на переменную, не её
значение; в аргументах npm и окружении запущенного web-контейнера секрета нет.

Проверки обёртки: `npm run test:private-packages`.

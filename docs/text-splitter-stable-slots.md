# Splitter: устойчивые связи разделов

При разделении текста с заголовками `[LIGHT]`, `[BACKGROUND / ENVIRONMENT]`
и другими именованными секциями `item-N` закрепляется за секцией, а не её текущим
номером в отфильтрованном тексте. Работает и при delimiter `[` без открывающей
скобки в результате разделения.

- Выключение бейджа в Extract/Prompt не удаляет связь: строка Splitter показывает
  «LIGHT — нет во входе» и передаёт пустой текст. Generate Image не получает
  описание другого слоя. Включение возвращает текст в прежний выход.
- Изменение тела или порядка уникальных именованных секций не меняет привязки.
- Повторяющиеся заголовки различаются по точному тексту, не по номеру появления.
  При неоднозначности прежний выход остаётся пустым, а не подменяется.
- Список без именованных заголовков сохраняет прежнюю позиционную семантику.
- Лимит 30 включает зарезервированные выходы. При заполнении можно использовать
  только отсутствующие несвязанные слоты; связанные никогда не переиспользуются.
  Не поместившиеся фрагменты отмечаются предупреждением.
- `itemKeys` сохраняется в документе рядом с `items`. Это внутренний контракт,
  не MCP setting. Идентификаторы связей, Undo и динамические порты не меняются.
- Старые документы получают ключи из последнего сохранённого набора `items`.
  Если связи уже были смещены старой версией, их исходное намерение неизвестно:
  нужно проверить подключение именованных строк, автоматически угадывать его нельзя.
- Новые публикации закрепляют ключи в runtime config `text.split`. Старые
  immutable публикации без ключей продолжают работать позиционно. Коллекция
  `items` не включает пустые слоты, отдельный отсутствующий `item-N` возвращает `''`.

Проверки: `text-splitter-slots.test.ts`, node help/catalog, dynamic ports,
Studio runtime descriptor и production text handler. Платные AI-вызовы не нужны.

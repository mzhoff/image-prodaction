- All: совместимые модели, A–Z по отображаемому названию, без Auto Router.
- Most popular: успешные `generation_job` пользователя за всё время во всех Workspace. Одно задание = один запуск, независимо от количества попыток и записей usage. Ошибки, локальные операции и задания service client исключены. Равные счётчики сортируются A–Z. Без истории список пуст.
- Favorite: порядок добавления, затем пользовательская сортировка в Настройки → Аккаунт → Избранные модели. После удаления и повторного добавления модель оказывается последней.
- Поиск фильтрует активный список без изменения его порядка. Звезда не выбирает модель и не закрывает меню; доступна при hover, клавиатурном фокусе и на touch.
- Последняя вкладка (по умолчанию All) и избранное независимы для text/image/video/audio, общие для разных нод одного типа. Поднабор ноды ограничен её существующим каталогом и возможностями.

## Хранение и границы

Аддитивная миграция `0030_account_model_preferences` создаёт `account_model_preference` с ключом `(user_id, modality)`. Это настройки текущего локального аккаунта, без переноса Identity/Workspace или изменения владения провайдерами. При недоступности модели её ID сохраняется в избранном для ручной сортировки/удаления, но не появляется в несовместимой ноде.

`GET/PATCH /api/account/model-preferences` получает пользователя исключительно из серверной сессии. Клиентский `x-account-id` — только предохранитель от отложенного запроса после смены аккаунта; он не выбирает владельца данных. Ответы private/no-store. API не принимает workspaceId/userId в теле. Добавление/удаление явно задаёт желаемое состояние; транзакционная блокировка одной строки предотвращает потерю изменений. Сортировка требует текущую revision и точное множество избранных моделей; конфликт не перезаписывает новый список.

Клиентский кэш изолирован по userId, общий для Canvas и настроек, обновляется при открытии селектора/настроек и возврате фокуса. Изменения отправляются последовательно, отображаются сразу и откатываются с сообщением при ошибке. Если настройки недоступны, выбор конкретной модели из All остаётся доступным; избранное не перезаписывается пустым списком.

Личные предпочтения не входят в граф, pinned pipeline, Node settings или MCP actions. Выбор вкладки/звезды не запускает AI и не меняет model ноды. Нового провайдера и новых параметров генерации этот интерфейс не добавляет.

## Проверка

Контрактные тесты проверяют сортировку, повторное добавление, независимость типов, конфликт ревизий, изоляцию кеша и откат ошибок. PostgreSQL-тест под `MODEL_PREFERENCES_TEST_DATABASE_URL` использует синтетические записи внутри откатываемой транзакции; проверяет разных пользователей в одном Workspace, одного пользователя в разных Workspace, ретраи и сервисные задания. E2E `model-selector.spec.ts` проверяет реальное API предпочтений, ноды всех четырёх типов, перезагрузку и сортировку из настроек. `image-generation-models.spec.ts` проверяет сохранность модельных параметров. Для проверки UI Most popular браузерный тест подставляет известные счётчики в ответ чтения; подсчёт реальных записей проверяется отдельно PostgreSQL-тестом. Платные вызовы в обоих браузерных сценариях перехватываются.

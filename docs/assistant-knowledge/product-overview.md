# Image Production

## Назначение продукта

Image Production — визуальная студия для сборки, редактирования, проверки и
публикации исполняемых AI-пайплайнов. Пользователь соединяет ноды в граф: данные
и результаты проходят от выходных портов одной ноды к совместимым входным портам
другой.

Продукт не является универсальной маркетинговой CRM. Его главный объект —
визуальный производственный пайплайн, который можно сохранить как документ,
переиспользовать как шаблон и запускать через поддерживаемый runtime.

## Основные сущности

- Workspace изолирует документы, библиотеку, подключения провайдеров и права доступа.
- Document хранит граф проекта, секции, ноды, связи и номер ревизии.
- Node выполняет одну ограниченную функцию: ввод, преобразование, генерацию,
  обработку, предпросмотр, экспорт или публикацию.
- Edge соединяет совместимый выходной порт с входным портом.
- Section визуально группирует части большого графа и может стать основой шаблона пайплайна.
- Library хранит доступные пользователю медиа-ассеты.

## Как собрать первый пайплайн

1. Создайте или откройте документ.
2. Добавьте ноду-источник: текстовый Prompt, Import image или Sketch.
3. Добавьте преобразование или генерацию, совместимую с типом выхода источника.
4. Соедините выходной порт источника с подходящим входным портом следующей ноды.
5. Добавьте Preview или Export image для проверки и выгрузки результата.
6. Сохранение документа происходит через сервер с контролем ревизии, чтобы одна
   вкладка не затёрла более свежие изменения из другой.

## Подключения AI-провайдеров

Продуктовые генерации и чат-ассистент — разные назначения расходов. Они могут
использовать один физический OpenRouter-ключ, но учитываются и настраиваются
логически отдельно. Ключи доступны только серверу и не должны попадать в браузер,
сообщения, документацию или журнал ответов.

## Что умеет ассистент на первом этапе

Ассистент отвечает на вопросы о продукте, подсказывает подходящие ноды и читает
краткую серверную сводку открытого документа. Он пока не создаёт ноды, не меняет
граф, не запускает генерации, не публикует и не удаляет данные. Такие действия
будут добавляться отдельно и только с явным подтверждением пользователя.

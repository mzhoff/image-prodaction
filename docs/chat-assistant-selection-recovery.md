## Реализация

Сценарий: пользователь отправлял выбор редактируемых элементов, но
ToolCallingChatAgent в ChatModule 0.12.0 терял `selectedAction`. После серверного
обновления форма снова выглядела неотправленной, модель получала лишь текст.

Исправление общей библиотеки — 0.12.1: metadata сохраняется и передаётся модели
в роли пользователя, включая IDs и referenceFrame; Retry сохраняет тот же ответ.
Это не разрешение на выполнение изменяющего инструмента.

Image Production дополнительно проверяет текущий ответ по сохранённому
опроснику той же conversation и workspace. Повторный вызов
`design_element_selection` после отправки возвращает `design-elements-selected`
со сделанным выбором, а не новую форму. Новое самостоятельное сообщение может
открыть новый опросник. Подтверждение preview перед изменением графа сохраняется.

Большие графы сначала раскладываются по уровням. Если обычная раскладка выходит
за 4000px canvas, применяется компактная многостолбцовая раскладка без потери
нод, связей, уменьшения карточек или пересечения существующего графа. Если места
действительно нет, подготовка остаётся заблокированной; сохранённые ответы не
должны запрашиваться повторно.

Проверки без live LLM: selected-action-agent в ChatModule; в Image Production —
design-selection-continuation, design-element-selection, pipeline-layout,
pipeline-build/update и consumer Retry. Старые потерянные metadata не
восстанавливаются выдумыванием; текстовая история остаётся без изменений.
